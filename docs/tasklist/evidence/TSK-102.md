# TSK-102 — inventory booking and all-item hold core

Status: ACCEPTED
Reviewer: Controller scoped source/diff review; acceptance limited to the internal booking/hold core.

## Delivered scope

- V16 stores VND, payment mode, policy, request hash/key and original 15-minute
  hold expiry; V14 stores immutable booking-item, room allocation and nightly
  charge/policy snapshots.
- Internal JDBC service accepts no client prices. It reads prices and plan
  restrictions server-side, validates per-room occupancy, builds all items and
  snapshots, then calls V14 `holdAll` inside the same transaction.
- Sorted type/plan/day locking follows the V14 protocol. PostgreSQL advisory
  locking provides same-guest/key serialization; same-body replay returns the
  original booking and changed-body reuse conflicts.
- An item/night shortage rolls back the complete booking. Whole-booking cancel
  and scheduled hold expiry release all commitments atomically.
- No public create-booking endpoint, quote/consent, attempts, payment confirmation,
  or real-money path is added; those need TSK-103/082. Legacy property exclusion
  remains unchanged.
