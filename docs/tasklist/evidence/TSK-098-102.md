# TSK-098 / TSK-102 — Sprint 2 Agent A implementation evidence

Shared scope/background record. The task-specific acceptance records are
[TSK-098](TSK-098.md) and [TSK-102](TSK-102.md); neither closes downstream or
release gates.

## TSK-098 — host inventory mutation core

- Host-owned room type and rate plan create/read/update/archive operations.
- Explicit immutable property sale mode; whole-place type count/capacity remains
  constrained by V14.
- Rate plans store a server-controlled whole-VND nightly price, allowed payment
  modes and frozen policy version. No client-supplied price is used by the booking
  core.
- Calendar is created/updated one day at a time using expectedVersion. DB capacity
  protection rejects OOO/total changes below held or confirmed commitments.
- Controller is under `/api/v1/host/**`, covered by existing HOST/ADMIN security
  rules; Spring CSRF remains enabled for session mutations. Ownership checks return
  not-found for another Host's property/type/plan.
- Archive preserves referenced items and commitments; an existing hold can still
  convert/release after archive. Mutations use the V14 property → type → plan → day
  lock order.

## TSK-102 — internal booking and hold core

- V16 adds plan nightly price plus VND, selected payment mode, policy version,
  idempotency body hash/key, optimistic booking version and original 15-minute
  inventory hold deadline.
- Internal JDBC transaction reads server-owned prices, validates per-room adults
  and child ages, captures policy/type/plan/allocation/night snapshots, inserts all
  selected items, and calls `InventoryCapacityService.holdAll` before commit.
- A PostgreSQL advisory transaction lock serializes same guest/key requests. Same
  request replays the same booking; changed body conflicts. All-item failure rolls
  back the header, items, snapshots and commitments.
- Whole-booking cancellation and scheduled expiration release all commitments in
  the same transaction. Legacy property exclusion and legacy booking path remain
  unchanged.
- Deliberately not public checkout: there is no quote/consent/requote path, no
  payment-attempt creation, no FULL/HYBRID amount allocation or IPN confirmation,
  and no booking-create HTTP endpoint. Enabling one before TSK-103/082 consent and
  financial composition would bypass the frozen contract. Taxes/discounts remain
  outside this core; real-money activation remains blocked.
