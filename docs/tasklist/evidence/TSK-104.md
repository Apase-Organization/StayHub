# TSK-104 — review/email/snapshot projections

**Status: implementation in progress; independent review/acceptance pending, 2026-10-24.** This records the current projection and transactional payload implementation. TSK-076 still owns delivery, deduplication/retry, SMTP failure handling and notification operations evidence; TSK-092 still owns completion/no-show/review authorization.

## Delivered

- V22 captures immutable listing and terms snapshots for new bookings. The snapshot retains listing details, stay/guest values, current price/fees/discount/total, payment mode, policy/request versions and the financial snapshot where available.
- Booking responses prefer the captured listing and the V15 financial snapshot, so a later title/city/price change or archive does not rewrite the returned booking name, payment mode, due-online or host balance.
- A deferred PostgreSQL trigger writes a `booking_notification_outbox` row on a supported booking status transition in the same transaction. Its JSON payload includes the frozen listing/terms and each item’s type, plan, quantity, room nights and total. The dispatcher does not exist in this task and must not be inferred from the outbox.
- Reviews remain one-per-booking, not one-per-room or item; the existing unique booking key is exercised with a two-room booking. Type context remains optional and is not added to the review schema.

## Verification

- `./mvnw -q -Dtest=BookingProjectionSmokeTest test` — PASS, PostgreSQL 16 Testcontainers; 1 test case, 0.614s case time (16.421s suite time including application/container startup).
- The test confirms a quantity-2 item emits one notification payload with quantity 2 and 2 room nights; the listing remains unchanged after the property title/city/price/status are changed; the financial projection remains HYBRID_DEPOSIT with 400,000 VND online and 1,600,000 VND host balance; a completed two-room booking has one review.
- Broad Maven/Compose/e2e checks were not run. No email was sent and no release/legal clearance was tested.

## Handoff / limits

TSK-076 can consume the outbox only after its own event contract, retry policy and SMTP-failure evidence are accepted. Existing rows created before V22 are not backfilled from today’s property values; their missing historical listing terms remain unknown rather than fabricated. TSK-113 UI work is not included.
